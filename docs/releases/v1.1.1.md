# v1.1.1 — 服务器产物兼容约定与部署说明

- 保留桌面 `override.js` 默认 `__flclashRules` 状态标记；服务器推荐使用 `server-policy.yaml`。
- 增加无秘密 subscription provider 示例和服务器本地组合步骤，说明完整路由策略导入与保存、启动、重启的区别。
- 按 mihomoctl v1.4.1 源码核对接口，修正文档中的 provider 引用关系、旧命令和过强的探针能力描述。
- 补充 provider、缓存路径、策略目标、YAML 格式和桌面标记回归检查；业务规则、节点过滤值和 `MATCH,DIRECT` 保持不变。

## 适用条件

`override.js` 用于 Clash Verge Rev / FlClash 桌面订阅脚本。mihomoctl **1.4.1 不直接兼容**该脚本的默认状态标记，`--flclash-compat` 也不能解决；不要手工删除生成物中的标记。

`server-policy.yaml` 是策略片段，不是可独立启动的完整配置。服务器必须本地提供 `subscription` provider，并由 mihomoctl 管理已有的 listener、认证及运行设置。完整策略导入会替换路由字段；必须预览核对后再保存。命令基于 v1.4.1 源码核对，未在生产服务器执行，也未验证真实订阅或业务可用性。

附件只包含无秘密生成物、占位 provider 示例、摘要和脱敏审核记录。填写真实 URL 后的文件、节点、认证、缓存和完整配置不得上传。`SHA256SUMS` 用于检查附件完整性；三方审核记录绑定本 Release 的确切提交 SHA。

仍需 mihomo-userctl 处理：默认标记兼容、导入序列化、校验超时/缓存/重复校验、provider 节点测速、权限诊断和 TUI 保存/运行状态反馈。
